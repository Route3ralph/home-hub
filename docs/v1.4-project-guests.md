# Home Hub v1.4: project guests

Status: built (migration `0011_project_guests.sql`, schema 11). The owner chose every recommendation in §7 on 1 Nov 2026.

A **project guest** is someone outside the family, such as an interior designer, who signs in with an emailed code like the family and sees only the projects a parent assigns them. In the examples and tests the guest is Riley Designer (riley@example.com), a made-up designer, assigned the made-up Kitchen project.

## 1. The approach

A guest is **not a member**. A `guests` table and a `project_guests` table give a guest their own narrow policies on `projects` and nothing else, so every existing `private.is_member()` policy keeps them out without being touched.

Rejected alternatives:

- **A `guest` role in `members`.** Every `is_member()` policy (36 tables) would let the guest in; each would need rewriting. Much larger change, much larger risk.
- **An edit link with no sign-in** (like the tutor link). Weaker: a forwarded link is a working login, and it can't be revoked per person without a new link.
- **A second Supabase project.** Two schemas, two deploys and sync between them, for one user. Overkill.

## 2. What a guest can and can't reach (audit of schema 10)

| Surface | For a signed-in non-member at schema 10 | From 0011 |
| --- | --- | --- |
| 36 tables | RLS on all, every policy `is_member()` or `is_admin()`; `people_confirm` revoked | Unchanged. Only `projects` gets guest policies, plus the three new tables (admins or members only) |
| 31 signed-in functions | Security-definer ones check `is_member()`/`is_admin()`; security-invoker ones (`agenda`, `day_text`, `heads_up`, `late_items`, `google_items`, `shopping_list`, `homework_week`) read through RLS and return nothing | Unchanged. `agenda` gives a guest only their own project's task dates (RLS), never events, tasks, meals or Google events; the guest pages don't call it |
| 22 token functions | Need a My day, confirmation or tutor token; a guest has none | Unchanged |
| `private` helpers granted to signed-in users | `is_member`, `is_admin`, `tz`, `food_other` (text only), `has_secrets(uuid)` (a yes/no for a directory id the guest can't learn) | Plus `is_guest_of` and `schedule_contractors` (for the policies) |
| Directory and account numbers | `contractors` member-only; `contractor_secrets` admins only | A guest reads the contractors on their project through `guest_contacts` (no notes, addresses or account details); never `contractor_secrets` |
| Share links | `get_shared_project` is anon-only and public by design | Unchanged. A guest copies the link while a parent has sharing on; can't turn it on, off or rotate it |
| `whoami()` | Null, so the site shows "Not on the list yet" | **Unchanged.** `send-email` treats any non-null `whoami()` as family; extending it would let a guest send hub email. The site calls `guest_whoami()` instead |
| `send-email`, `hub-jobs` | 403 (`whoami()` null; not an admin) | Unchanged: 403 |
| Morning email, My day | Built from `people`; a guest isn't a person | Unchanged. A guest gets no hub email |
| Sign-up hook | `hook_family_only_signup` allows only `members` emails | Also allows an address in `guests`. Same name, so no dashboard change |
| Google Calendar and the wall | Project task dates sync to the family calendar when "Show in Home Hub calendar" is on | A guest's schedule edits flow there too (intended). Only the family changes that switch |

## 3. Data model (migration 0011)

- `guests (email, name, created_at, created_by)`: who may sign in as a guest. `add_project_guest` refuses a member's address.
- `project_guests (project_id, guest_email, added_at, added_by)`: which projects each guest sees; goes with the project or the guest.
- `project_contacts (project_id, contractor_id, added_at, added_by)`: the contractors a guest added to a project. With the ones its schedule's trades link, they are "the contractors on the project".
- `projects.documents_url`: the project's shared folder, `https://drive.google.com/…` only.
- Policies on `projects`: a guest selects and updates the projects assigned to them (`private.is_guest_of`). No insert or delete. The trigger `projects_guest_guard` refuses a guest's change to the owner, the calendar switch, sharing or the share link (42501 "Only the family can change the owner, the calendar switch or sharing."), and a trade linked to a contractor not on the project.
- Functions: `guest_whoami()`; `guest_contacts(p_project uuid)` and `guest_save_contact(p_project uuid, p_contact jsonb)` for a guest; `add_project_guest(p_project uuid, p_email text, p_name text default null)`, `remove_project_guest(p_project uuid, p_email text)` and `remove_guest(p_email text)` for the parents. The exact tables, checks, messages and grants are in `docs/v2-design.md` §16.
- `hub_schema_version()` returns 11.

## 4. What the guest manages

- **Schedule**: the Gantt phases, tasks, dates, statuses, notes (both kinds: "private notes" are working notes kept off the share link) and trades of each assigned project; its name, summary, status, start date and days off.
- **Contractors on the project**: name, company, trade, phone, email, website. Never account numbers, directory notes or addresses, and never the rest of the directory. **Contractors** lists them; **+ New contractor** adds one (a directory entry, on this project); **Edit** changes one that has no account details saved. **Trades & contractors** links a trade only to a contractor on the project.
- **Documents**: the project's **Settings** has a **Documents folder** (a Google Drive address); the **Documents** button opens it in a new tab for everyone in the family and the guest. Only the parents and the guest change it (the database refuses an adult); it is never on the public share link.
- **Messages**: Text, WhatsApp, Share and Open in my email work from the guest's own phone. "Send email now" (the hub's `send-email`) is hidden for a guest.
- **Not for a guest**: the project's family to-dos (the Tasks card, which names family members), the owner, Show in Home Hub calendar, turning sharing on or off, a new share link, a new project, deleting one.

## 5. Assigning and removing access

1. Project page → **Guest access** (parents only): a name and an email → **Give access**. The guest can then sign in with a code.
2. End of job: the same place → **Remove**. Access ends on the guest's next request (RLS checks every call); no sign-out needed. They keep a sign-in that shows "No projects are shared with you right now".
3. Settings → **Project guests** (parents only) lists every guest and their projects, with **Remove guest** (every project, and the sign-up hook turns the address down). Their Supabase login stays until deleted by hand (Authentication → Users); it sees nothing.

## 6. The guest's hub

- **Pages**: Projects only (a module registered with `guest: true`; the core shows guests no other). One assigned project → straight to it, with no back link; several → the list (no New project); none → "No projects are shared with you right now."
- **Header**: Home Hub, the Projects tab, the guest's name, Sign out. No Add, no More, no bottom bar. Any other address (`#/`, `#/tasks`…) shows their project.
- **Requests**: `whoami`, `hub_schema_version`, `guest_whoami`, `clock`, `projects` and `guest_contacts` (and `guest_save_contact` when they save one); never `people`, `household`, `contractors` or any other table.
- **Emails**: none besides the sign-in code. A weekly project summary could come later; it needs `hub-jobs` and a consent step.

## 7. Decisions (the owner, 1 Nov 2026: every recommendation)

1. **Role**: a non-member with their own tables and policies, as above.
2. **Gantt private notes**: the guest sees and edits them.
3. **The project's family Tasks card**: hidden from guests.
4. **Contractors**: the guest sees the ones on their projects (name, company, trade, phone, email, website) and can add new ones and edit those without account details.
5. **Share link**: the guest copies it; only the family turns it on or off.
6. **Documents link**: Drive addresses only; the family and the guest open it; only the parents and the guest change it; never on the public share link.
7. **Assigning**: per project (Guest access), plus a Project guests card in Settings.
8. **Guest landing**: straight to their project when there's one; no emails besides the sign-in code.
9. **Hub file storage**: not built. Drive already gives versions, previews and per-person sharing; hub storage would add an access surface in a public repo for no gain.

## 8. Deploy order

1. Merge the site. It reads `hub_schema_version()`; the guest pages, Guest access, the Project guests card and the documents folder need 11, so nothing changes on 10 (`tests/realdb/v10db.test.js`). No Edge Function or `cron.sql` change.
2. The owner pastes `supabase/migrations/0011_project_guests.sql` in the SQL Editor (it refuses without 0010, or twice; "set back to 10" means `hub_schema_version()` was changed by hand: make it return 11 again).
3. A parent opens the project → Guest access → Give access; the guest signs in with a code.

Undo (not needed: with no guest added every answer is 10's): the migration's header writes it out (`docs/v2-design.md` §16).
